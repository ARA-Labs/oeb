READING KEY - Chip-Bench hill-climb task {task} ({title}).

One coding agent ({model}, scaffold {agent}) works ALONE in a workspace copy of a chip-design optimisation task under a wall-clock cap. It starts from a correct but unoptimised baseline design plus a frozen local scorer (`make score`), and must make ONE tool-measured metric ({metric}, direction: {direction} is better) as good as possible while every functional guard (differential simulation against a golden model, formal equivalence, lint, resource caps, determinism) keeps passing. A design that fails any guard scores 0, so the agent must always leave a passing design on disk. Hidden grading happens AFTER the run on hidden workloads/seeds/variants the agent never sees; that verdict is the outcome oracle and is not in this record (world.json declares it).

World reading: running `make score`, the simulators (verilator, iverilog, the harness's C++ trace players), synthesis and place-and-route (yosys, nextpnr, abc), formal tools (sby / SymbiYosys), compilers (g++, riscv gcc) and any agent-written model or search script observes the world - the design's measured behaviour on the PUBLIC workloads (a representative sample of the hidden set; over-fitting to it is a known trap the READMEs warn about). File reads and edits (RTL .sv/.v, C++ policy files, yosys recipes, SDC constraints) author the design and settle nothing until something is run. Background-task polls (`taskoutput ...`) watch a running simulation and return its output. The agent's own `make score` reads are the only in-run ground truth: each appends one line to build/score_log.jsonl - the climbing curve.

The local score line the agents saw was the hc-0.1.0 CAPPED score (max 1.25 and against the old expert reference); the raw metric printed next to it was uncapped. Several agents kept improving the metric after their local score pinned at 1.25 - read the metric, not the score, when judging what the agent learned.

Typical claim shapes: "<microarchitectural/structural change> improves <metric> by X on <workload>", "<change> breaks guard G (equivalence / lint / storage budget)", "the public traces show <pattern>, so <design choice> should pay". Evidence hierarchy: a reasoning-only estimate < a software model / synthetic test < `make score` on the public set (the graded material reachable in-run) < the hidden grade (never reachable).
